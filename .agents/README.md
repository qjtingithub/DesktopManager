# DesktopManager 子代理调用说明

这些文件是项目内的角色提示模板。当前协作工具不会按文件名自动选择角色，因此根代理在创建子代理时，必须要求它先阅读 `AGENTS.md` 和对应角色文件。

## 选择角色

- 涉及 Explorer、COM、Win32、图标 PIDL 或图标坐标：使用 `shell-integration-engineer.md`。
- 涉及 WPF 窗口、透明度、拖动、缩放、点击穿透或视觉状态：使用 `desktop-ui-engineer.md`。
- 涉及本地日程、提醒、番茄钟、计时恢复或统计：使用 `productivity-widget-engineer.md`。
- 涉及需求符合性、测试充分性、回归风险或合并前审查：使用 `quality-reviewer.md`。

同一个子任务只指定一个主角色。跨角色任务先由根代理拆开；不能安全拆开时，由根代理串行完成集成。

## 标准调用模板

根代理调用时应发送完整任务，而不是只发送角色名称：

```text
请先完整阅读：
1. AGENTS.md
2. .agents/roles/<role-file>.md

任务目标：<一个可验证的目标>
写入权限：<只读 / 仅允许修改以下路径>
允许修改：<精确路径；只读任务写“无”>
禁止修改：<共享文件和其他代理范围>
成功标准：<可观察结果>
验证方式：<命令或手工步骤>

若规则、代码或目标互相矛盾，先停止并向根代理报告，不要自行扩大范围。
完成时报告结论、修改文件、验证结果和剩余风险。
```

## 并行与串行规则

- 根代理先建立可编译的最小解决方案、测试项目、路径布局和公共坐标接口，再派发写代码任务。
- Shell 调研与 UI 假数据原型可以并行，因为它们使用预先分配且互不重叠的路径。
- 公共接口定义、项目文件更新和最终接线必须串行，由根代理负责。
- 质量审查在实现完成后执行；审查员不得一边审查一边悄悄改生产代码。
- 效率组件只在核心 Demo（Shell、UI、集成和质量审查）全部通过后启动，避免为不可行的主方案提前开发附属功能。

## 建议的任务名称

- `shell_probe`：Shell 可行性验证。
- `desktop_overlay`：透明桌面框原型。
- `productivity_widgets`：日程和番茄钟。
- `demo_review`：Demo 验收与风险审查。

任务名称只是运行时标识；真正约束来自 `AGENTS.md`、角色文件和本次任务说明。
