## 验证中发现并修复的问题

1. Shell 枚举标志遗漏普通非文件夹项目，导致真实文件未全部列出。已同时启用文件夹与非文件夹枚举标志。
2. 使用绝对 PIDL 直接调用当前桌面视图的位置写入无效。现在写入前重新枚举当前视图，以稳定 parsing identity 精确匹配并使用当前 child PIDL。
3. WPF XAML 初始化过程中滑块事件过早触发。现在初始化期间抑制视觉状态回写。
4. 在 `LocationChanged` 输入同步回调内直接调用 Explorer COM 会出现 `RPC_E_CANTCALLOUT_ININPUTSYNCCALL`。现在只累计位移，并由后台串行工作器执行 Shell 写入；关闭/恢复会先停止队列并与当前写入同步。
5. 恢复 JSON 曾只信任记录本身。现在恢复前重新验证固定白名单路径与稳定身份；异常记录不会触发任何坐标写入。

## 尚需人工覆盖的非阻塞场景

- 分别在 100%、125% 和 150% 显示缩放下检查图标与分区的视觉对齐。
- 在一次移动过程中手动重启 Explorer，确认当前批次停止，下一次启动先处理保留的恢复记录。
- 在真实鼠标操作下逐项检查锁定后的单击、双击、右键和拖选是否完整穿透到桌面。
- 在 `Ctrl+Alt+E` 被其他程序占用的机器上检查失败提示是否足够明确。

这些项目不影响当前技术链路的可行性结论，但应在进入完整产品阶段前纳入手工回归清单。
